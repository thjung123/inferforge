# Triton model repository

Everything here except the python-backend `model.py` files is generated by the
builder from a preset (`builder/presets/*.yaml`). `POST /models/register` compiles
the model to a TensorRT engine, generates the `config.pbtxt` for each step and the
ensemble, writes them into this directory, and loads them into Triton — see the main
README, "Build pipeline". The presets are the single source of truth; the committed
configs are regenerated from them, and the `.plan` engines are built at runtime and
not committed.

Each model type is served as an ensemble of python-backend processors around one or
more TensorRT engines.

BERT — text → embedding:

```
bert_ensemble/       # ensemble
bert_preprocessor/   # tokenizer (python backend)
bert_encoder/        # TensorRT engine
bert_postprocessor/  # masked mean pooling (python backend)
```

CLIP — image + text → similarity:

```
clip_ensemble/            # ensemble
clip_image_preprocessor/  # image fetch + preprocess (python backend)
clip_text_preprocessor/   # tokenizer (python backend)
clip_visual/              # TensorRT engine (vision tower)
clip_text/                # TensorRT engine (text tower)
clip_feature_merger/      # cosine similarity (python backend)
```
